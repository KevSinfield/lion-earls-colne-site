# The Lion, Earls Colne: website and newsletter

Client project for Craig's pub (The Lion, High Street, Earls Colne CO6 2PA). Static site plus a weekly email newsletter. Mock-up stage: nothing is deployed or sent yet. Background, decisions and open items are in memory (`lion-earls-colne-site`); don't repeat them here.

## Run it

- Preview the site: serve this folder over http (the menu panel loads JSON, so opening the file directly won't work), e.g. `python3 -m http.server 8765`, then open http://localhost:8765. The plain Python server lets the browser cache old scripts; if a change doesn't show, serve with a no-cache header instead.
- Menu extractor tests: `tools/.venv/bin/python -m unittest discover -s tools -v`
- Newsletter preview: `python3 tools/render_newsletter.py --content tools/samples/newsletter-sample.json --sample --out newsletter/preview.html`
- Add a menu: `tools/.venv/bin/python tools/extract_menu.py MENU.pdf --expect-venue Lion --merge data/menu.json`

## Rules for this project

1. **Lion only.** The Chapel Inn shares the sending mailbox (the Chapel office mailbox). Never put Chapel menus, offers or events on the Lion's site or newsletter. Keep `--expect-venue Lion` on every extractor run.
2. **Nothing goes out without Kev's go-ahead in the last message:** no deploys, no publishing, no email or newsletter sends, no changes to Craig's DNS or Microsoft 365.
3. **Never guess Lion facts.** Hours, prices, phone, booking link, history and dates come from the Lion's own material or a cited source. Anything unconfirmed gets a visible `TODO` (red text) and is listed in memory. The old "since 1678" claim is unverified: leave it out.
4. **Keep it a mock-up until told otherwise:** the page carries `noindex` and `robots.txt` disallows everything. Remove both only when the site goes live.
5. **Email must not depend on images.** The newsletter uses a live-text masthead and web-safe fonts (Times New Roman/Arial), light cream background. No dark newsletter, no image logo (it failed to load in Apple Mail).
6. **One source of truth per thing:** menus in `data/menu.json`; hours, events, contact details in `js/data.js`. Don't copy them into other files.
7. **No Chapel data in `data/menu.json`.** The demo tab of the Chapel's weekend specials was removed on 8 Oct 2026; don't add it back. Test with `tools/samples/` and a scratch copy of the menu file instead.
8. **All "Book a table" links go through Stampede, nothing else.** Use the Lion's own Stampede link (not the Chapel's) in `bookingUrl` in `js/data.js` and `VENUE["book"]` in `tools/render_newsletter.py`. Until it exists they point to the Find us section. Never a `tel:` link on a Book button. (A plain phone number as contact info is fine.) Waiting on the Stampede set-up.
9. **Fonts:** headings use Playfair Display (Kev chose it on 27 Oct 2026; Cormorant made the digit 1 look like a capital I). Body is Inter. Full-height "lining" numbers are forced site-wide in `css/style.css` with `!important`, because the `font:` shorthand elsewhere resets them. Don't remove that rule. The newsletter uses Times New Roman/Arial (web fonts don't work in email). Georgia is out: its numbers are old-style and can't be switched to lining, so the 1 looked like an I (checked and changed 27 Oct 2026).
10. **Every menu must pass the completeness check before it goes on the site: everything on the menu, nothing missing, nothing invented** (Kev's rule, 28 Oct 2026). Never pick out "the bits we want". `tools/menu_check.py` compares every printed line of the source (PDF, or a picture read by the Mac's OCR) against our menu data in both directions, plus a control total: count the dishes on the printed menu yourself and pass `--expect-dishes N`. `extract_menu.py` runs it on every PDF and refuses to merge on a fail (`--force` only if checked by hand), and on merge keeps the Lion's PDF as `menus/<id>.pdf` for the download button. NOTE: the PDF reader in `extract_menu.py` was built for the Chapel's weekend-specials layout (needs a date and a price on each dish line), so it will stop on the Lion's own menu PDFs until it is adapted to their real layout (two columns, serif dish names, sans descriptions, often no prices). Adapt it against the first real Lion PDF. Pictures: run `menu_check.py` yourself. The Main Menu was checked with: `tools/.venv/bin/python tools/menu_check.py --menu data/menu.json --id main-menu --image "lion small plates.jpg" --image "lion pub classics.jpg" --image "lion pizzas.jpg" --allow-source "WOOD-FIRED PIZZA" --accept starting --expect-dishes 27` (pass). Menu pages show the whole menu: no dietary or other filter buttons.
11. **No em dashes in copy.** Write British.

## Layout

- `index.html`, `css/`, `js/`, `images/`: the site (`js/data.js` holds the editable facts)
- `js/bar.js`: the one solid sticky header bar used on every page (built into `<header id="chrome-head" data-active="...">`). About 100px on desktop, shrinks on scroll, slim 64px with a menu drawer on phones. Edit the nav links here, nowhere else. Added 27 Oct 2026 (private repo only until Kev says push it live).
- Home page "What's on next" section (28 Oct 2026, events concept B): under the buttons row, the next two events as big square posters on sand (Kev chose this after the small-card strip looked lost), built in `js/main.js` from `data/sample/events.json` (real events only: entries with `sample: true` are never shown). Dated events first, soonest first; with fewer than two it fills from the regular weekly nights. Past events drop off by date. The What's on button says "Next up, <short title>, Sat" and the menu button says what the kitchen is doing ("Kitchen from 5:30pm"). Set `short` on an event for a short button title; set `image` for its poster or photo. `?at=2026-10-31T18:00` previews another date and time. Max two cards on purpose: no galleries.
- Home page layout (28 Oct 2026, "concept B" from `docs/concepts/`): cream hero over the frontage, then three full-width picture-and-text bands (pizza plates and pub classics, Sunday roast, what's on), then history, sign-up and find us. Each band is one photo, one short line, one action. Kev's rule: keep it from turning into a photo gallery, so no photo grids or carousels. The three band photos (`images/pizza.jpg`, `roast.jpg`, `poker-night.jpg`) are cropped from the Lion's own Facebook posts of 16, 23 and 26 Oct 2026, with the Lion logo stamp cropped out; Kev said showing the people is fine as they posted it themselves. Still worth Craig's OK before it goes live, and better originals would be sharper (the poker one is low-res). Originals are in `~/Downloads/lion-fb-*.jpg`. A slot with no photo shows a warm placeholder; use class `ph--img` plus a `background-image` to fill one (see `.ph` in `css/style.css`). Private repo only until Kev says push it live.
- Find us (28 Oct 2026, Kev's pick: concept 1 with a map): a still map picture (`images/map.jpg`) behind the details card on the left, hours on light cream on the right. The map is a one-off stitch of OpenStreetMap tiles (zoom 17, warmed to the site's colours, pin at OSM's node for the Lion pub: 51.92815, 0.69855), made with Pillow (installed in `tools/.venv`). It is a still picture on purpose: no live map means no cookies and no third-party requests, so the privacy page stays true. Keep the "Map © OpenStreetMap contributors" credit (required by the licence). Tapping the map opens Google Maps (`mapsUrl` in `js/data.js`). Don't swap in a Google embed without adding a cookie banner.
- The "This week at the Lion" band's photo follows the day of the week (`PHOTOS` map in `js/main.js`: Sun roast, Mon the front of the pub, Tue poker, Wed pizza, Fri small plates (`images/tapas.jpg`, cropped from the dishes shot in the 23 Oct Facebook post), Thu and Sat the pizza as a stand-in). Today's row is highlighted and the photo carries a "Today: ..." label. Thursday and Saturday need their own photos (bar and evening shots) when Craig supplies them. `?at=` previews another day.
- "Our history" opens with a wide photo strip of the building that fades into the cream at the bottom only, with the title over it (28 Oct 2026, Kev's choice B from `docs/concepts/split-*.html`). The photo is `images/lion-front.jpg`, a crop of the Lion's Facebook cover photo showing the pargeted plasterwork and the painted "Bar & Dining" lettering (cropped above the banner and the two people). Clean edge at the top, fades into the page at the bottom only. Swap it via `.strip__bg` in `css/style.css`.
- The sign-up is styled as a ticket on deep red (28 Oct 2026, Kev's choice from four concepts in `docs/concepts/signup-*.html`); the stub says "First to know" (Kev's pick over "Admit one", "Save the dates" etc.), with the crest cut from the logo. ## Git

Two repos, one folder:
- `origin` = private working repo (`KevSinfield/lion-earls-colne`). Normal commits and pushes go here.
- `public` = public copy (`KevSinfield/lion-earls-colne-site`), created 8 Oct 2026 from a history-free branch (`public-release`) so no old commits are exposed. Never push `main` itself to `public`. To update it, only when Kev says so: first run `python3 tools/stamp_version.py` (stamps every css/js link with a fresh `?v=`, so browsers and GitHub Pages never serve a stale copy; commit the result), then scan the tree for mailbox addresses and secrets, then make a commit of the current tree whose only parent is `public/main` (`git commit-tree <tree> -p public/main`) and push that as a normal fast-forward. If GitHub's Pages deploy fails with a 500, request a fresh build (`gh api -X POST repos/KevSinfield/lion-earls-colne-site/pages/builds`) rather than waiting.

GitHub Pages is on for the public repo (turned on 8 Oct 2026): https://kevsinfield.github.io/lion-earls-colne-site/ (serves branch `main` of `public`, so it only changes when `public` is updated). It is a mock-up and `noindex`.

This folder is listed in `~/Dev/.gitignore`, so the dev-sync job does not track it. Co-Authored-By trailer on commits. No force-pushes without Kev's say-so (the auto classifier blocks them).
